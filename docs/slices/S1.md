## Keputusan arsitektur yang dibangun di S1 (dipakai semua slice berikutnya)

**Lapisan kompatibilitas Inertia** agar komponen halaman React Laravel dipakai ulang hampir apa adanya:
- `@inertiajs/react` → modul pengganti (`Link`, `Head`, `usePage`, `router`, `useForm` minimal) dengan DOM keluaran
  sama; props bersama dari `HandleInertiaRequests::share` dihitung di server Next.js.
- Ziggy `route()` → pengganti dengan daftar rute dari `sigap/routes` (grup per peran seperti `config/ziggy.php`).
- Halaman = Server Component (memuat props seperti controller) → komponen klien yang sama dengan Laravel.
- Navigasi antar halaman yang belum pindah tetap tautan biasa (full reload) — perilaku terlihat sama.

## Arsitektur kompatibilitas Inertia (dibangun programmer 1, dipakai semua slice berikutnya)

Tujuan: komponen halaman React Laravel (`sigap/resources/js/**`) dipakai ulang tanpa edit JSX/`className`, dengan DOM
hasil render identik. Semua keputusan di bawah diuji mesin (lihat "Bukti").

### 1. Komponen disalin ke `web/`, bukan diimpor langsung dari `sigap/`

| Pertimbangan | Impor langsung `sigap/resources/js` | Salin ke `web/src` (dipilih) |
|---|---|---|
| Turbopack / standalone | alias `@/` bentrok (`@/` di sigap = `resources/js`, di web = `src`); paket (`react`, `lucide-react`) diresolusi dari `sigap/node_modules` bila ada → dua salinan React; butuh `resolveAlias` untuk tiap paket | resolusi Next.js biasa, satu React |
| `typecheck` / `lint` | tsconfig web memeriksa berkas sigap dengan alias yang salah | normal; aturan React Compiler yang tidak bisa dipenuhi salinan dimatikan khusus berkas salinan |
| CSS (`cek:css` IDENTIK) | Tailwind tetap memindai `sigap/` | sama: Tailwind tetap memindai `sigap/` (`css-statis.mjs`), jadi `className` salinan **harus** sama persis — dijaga test |
| S17 (hapus `sigap/`) | semua impor harus dipindah sekaligus di akhir (risiko besar di akhir) | tinggal hapus test penjaga + arahkan Tailwind ke `web/src` |
| Satu sumber kebenaran | ya | dijaga mesin: `tests/unit/inertia/salinan.test.ts` gagal bila salinan ≠ sigap (selain penulisan ulang impor) |

Aturan salinan ada di **satu** tempat, `web/scripts/salinan-sigap.mjs`:
- `SALINAN`: daftar berkas `resources/js` yang sudah dipakai halaman Next.js. Slice baru menambah entri lalu
  menjalankan `node scripts/salinan-sigap.mjs salin`.
- Pemetaan: `components/sigap/*` → `src/components/contact-center/*` (§10.1), `lib/sigap.ts` → `src/lib/contact-center.ts`,
  `pages/*` → `src/halaman/*`, sisanya jalur sama di `src/`.
- Penulisan ulang yang diizinkan hanya: impor `@inertiajs/react` → `@/lib/inertia`, `@/components/sigap/` →
  `@/components/contact-center/`, `@/lib/sigap` → `@/lib/contact-center`, dan `'use client'` di awal berkas `src/halaman/**`.
- `sigap/public` (images, geo, favicon, logo, robots) disalin byte-identik ke `web/public` (§8.1); diperiksa SHA-256.
- Perbaikan bug Laravel yang ikut di-port: ubah di `sigap/` (lewat proses biasa), lalu `salin` ulang. Jangan pernah
  mengedit salinan dengan tangan.

### 2. Modul pengganti `@inertiajs/react` (`web/src/lib/inertia`)

Hanya yang dipakai halaman yang sudah pindah. Yang belum dipakai **tidak diekspor** (galat kompilasi) atau melempar
galat jelas — tidak pernah diam-diam berperilaku lain.

| Ekspor | Perilaku | Belum didukung (galat) |
|---|---|---|
| `Link` | `<a {...props} href>` dengan urutan atribut sama dengan `createElement` Inertia; href dinormalkan seperti `mergeDataIntoQueryString`; klik = navigasi biasa browser (halaman dimuat penuh) | `method`, `as`, `data`, `prefetch`, `replace`, `preserveScroll/State`, `only/except`, callback kunjungan |
| `Head` | port `Head` + `createHeadManager` 2.0.3: tag `<meta …>` dikelola sebagai elemen ber-atribut `inertia` di `<head>` (beda dari aslinya: nilai atribut di-escape `&`/`"`, jadi nilai berkutip tidak bisa menambah atribut); judul lewat callback `title` app.tsx (`judulApp` di `src/lib/judul.ts`) | — |
| `usePage` | objek halaman utuh (`component`, `props`, `url`, `version`, `clearHistory`, `encryptHistory`) | — |
| `router.visit(url)` | GET tanpa data → `location.assign` (callback tidak dipanggil karena dokumen diganti) | method lain, data, fungsi router lain |
| `useForm` | tidak diekspor — slice formulir pertama menambahkannya (submit lewat Server Action, pola redirect-back) | |

`<InertiaApp>` (`src/lib/inertia/app.tsx`) = `createInertiaApp` + `<App>` untuk satu halaman:
- **Halaman dirender hanya di browser**, seperti Laravel (Inertia tanpa SSR): server mengirim `<div id="app">` kosong,
  lalu React mengisinya setelah hidrasi. Alasannya paritas DOM: render klien React menulis atribut dengan urutan
  berbeda dari render server (mis. `<img>`: klien memasang `src` paling akhir, SSR paling awal), dan snapshot DOM
  suite paritas membandingkan `outerHTML`. Efek samping lain yang ikut sama: tema/aksesibilitas dibaca dari
  localStorage sejak render pertama, portal panel aksesibilitas, daftar isi StaticShell.
- Wrapper `<div id="app">` dipertahankan. Tidak ada CSS/komponen yang memakai `#app`, tetapi selector luapan suite
  paritas berjalan sampai `<body>`, dan strukturnya jadi sama persis. `data-page` tidak diperlukan (props lewat RSC).
- Satu-satunya `<title>` milik React ada di `<InertiaApp>` (awal "Contact Center" seperti `<title inertia>` Blade,
  lalu judul dari `<Head>`). Root layout **tidak** memasang judul metadata: React mengklaim `<title>` pertama yang
  belum dimiliki setiap kali `<title>` React terpasang, jadi dua pemilik saling menimpa (terbukti: metadata Next.js
  yang dialirkan belakangan memulihkan "Contact Center"). Halaman non-Inertia boleh memakai `metadata.title` sendiri.
- Persistent layout (`Component.layout`) belum didukung → galat.

### 3. Ziggy `route()`

- `web/scripts/rute-ziggy.mjs` menjalankan `php artisan ziggy:generate --group=<public|warga|admin>` dan menulis
  `src/server/inertia/ziggy-rute.json` (di-commit; test membandingkannya ulang dengan Laravel bila PHP + vendor ada).
- `src/server/inertia/ziggy.ts` memilih grup seperti `@routes($ziggyGroups)` app.blade.php: tamu/pegawai `public`,
  warga `public+warga`, admin `public+admin`; `url` = origin aplikasi (APP_URL), `port` dari URL itu. Tabel admin
  hanya dikirim ke admin (A-14) dan tidak ada di bundle klien (diperiksa: chunk klien tidak memuat nama rute admin).
- `<InertiaApp>` memasang global `Ziggy` + `route` di browser sebelum halaman dirender. `src/lib/ziggy.ts` = port
  `route(nama, params, absolute)` Ziggy 2.6.4 (template, parameter wajib/opsional, `wheres`, binding model, sisa
  parameter → query RFC 3986), diuji terhadap Ziggy asli. Belum: `route()` tanpa nama (`current()`, `has()`),
  `defaults`, domain rute, query bertingkat → galat. `route()` saat render server tidak tersedia (halaman dirender di
  browser). Saat S1 tidak ada halaman hidup yang memanggil `route()` (hanya kode starter kit yang tidak dipakai).

### 4. Props bersama & render halaman

- `src/server/inertia/props-bersama.ts` = `HandleInertiaRequests::share` + `errors` Inertia: `errors`, `name`, `app`,
  `auth.user` (id, name, username, role, is_admin), `chat_unread`/`chat_waiting`/`rujukan_perlu` (di-query hanya untuk
  admin, seperti closure lazy), `recaptcha.site_key`, `assistant` (env `AI_ENABLED`, `AI_SERVICE_LABEL`), `flash`
  (status/success/error dari sesi Next.js). Urutan kunci sama. Sesi `errors` (galat validasi) belum ada padanannya →
  galat jelas; slice formulir pertama menambahkannya.
- `renderInertia(Komponen, 'public/xxx', props?)` (`src/server/inertia/halaman.tsx`) = `Inertia::render`: page
  `src/app/(publik)/xxx/page.tsx` adalah Server Component yang memuat props (seperti controller) lalu mengirim
  referensi modul klien `src/halaman/**` ke `<InertiaApp>` (props tidak diserialisasi dua kali).
- `url` objek halaman dihitung proxy dari URL asli (`x-cc-url`, selalu ditimpa) persis `Response::getUrl`
  inertia-laravel 2.0.28 (garis miring akhir, query diurutkan RFC 3986). `version` = `null` (tidak ada kunjungan XHR).

### 5. Rute, sesi, redirect

- Halaman S1 tidak punya middleware rute (`langkahRute` → `[]`): tamu, warga, admin boleh; sesi tamu dibuat untuk GET
  dan cookie sesi + `XSRF-TOKEN` dipasang seperti grup `web`.
- `Route::redirect` (web.php:36-38,45,68,70) dijawab di tumpukan web proxy setelah sesi & CSRF: 301, `Location`
  relatif, query dibuang, isi HTML RedirectResponse Symfony, tanpa `Cache-Control`, semua verb `Route::any` kecuali
  `POST /pengaduan` (rute `pengaduan.store.legacy`, belum dipindah).
- `skipTrailingSlashRedirect`: `/panduan/` dilayani 200 seperti Laravel (bawaan Next.js 308).
- Berkas publik (`images/`, `geo/`, favicon, logo, robots) tidak melewati proxy (di produksi Laravel dilayani nginx
  tanpa sesi); gambar mendapat `Cache-Control: public, max-age=604800` seperti nginx.
